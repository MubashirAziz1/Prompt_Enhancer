# Domain docs

This repository uses one root `GLOSSARY.md` and a root `docs/adr/` directory.

Before exploring an area, read the glossary and any ADRs relevant to the work.
If either is absent, continue. Domain modeling adds glossary entries and ADRs
as terms and decisions are settled.

Use the glossary's terms in issue titles, proposals, hypotheses, and test names.
If a term is missing, check whether the project already uses a different term
for the concept and record genuine gaps for domain modeling.

If a proposal conflicts with an ADR, cite the ADR and explain why the decision
is worth revisiting.
